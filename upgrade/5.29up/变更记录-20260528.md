## P1 · 用户端一键进入管理后台（admin SSO 按钮）

### 起因

平台同一个人可能既是普通用户（用 user 身份在前台对话）又是 admin（管后台）。
当前要进管理后台必须知道 `/admin/login` 路径 + 重新输用户名密码。**痛点**：
- 多数 admin 已经在用户端登录了 —— 让他再输一遍密码体感很重
- 移动端打字麻烦更明显

### 设计要点

**架构基础（已具备，无需改）**：两套 cookie 互不冲突，**可以同时存在**：
- `ai_portal_token` — 用户态
- `ai_portal_admin_token` — 管理后台态
- middleware 进 `/admin/*` 时只看 admin cookie，颁 admin cookie 完全不影响 user cookie

**核心机制**：用户在前台已登录 → 后端**重新查 DB**确认仍是 admin → 颁发
admin cookie → 新 tab 打开 `/admin/dashboard`。

### 改动 3 块

#### 1. 后端 · `GET /api/me` 加 `isAdmin` 字段

[`app/api/me/route.ts`](../../app/api/me/route.ts)：

```ts
const isAdmin =
  user.role === "super_admin" ||
  user.role === "system_admin" ||
  user.role === "org_admin";
return NextResponse.json({ ...原字段, role, isAdmin });
```

只看 `users.role`；不查 `admins` 表 —— 那张表是系统内置账号（默认 admin），前台
登录通道只允许手机号 / 用户名，不会出现 admins 表用户。

[`lib/types.ts`](../../lib/types.ts) · `UserInfo` 加可选字段 `isAdmin?: boolean`。

#### 2. 后端 · 新 endpoint `POST /api/auth/elevate-to-admin`

[`app/api/auth/elevate-to-admin/route.ts`](../../app/api/auth/elevate-to-admin/route.ts) ·
**用户态已登录 → 颁 admin cookie**。

**安全设计（小B 复审重点）**：

| 检查 | 做法 | 复用 |
|---|---|---|
| ① user token 有效 | `getCurrentUser()` | lib/auth.ts |
| ② **重查 DB**（不信 JWT 里的 role —— 可能是几天前签的、中间被降权） | `SELECT id,phone,username,role,status,tenant_code FROM users WHERE id=...` | — |
| ③ status 必须 `active`（拒 deleted / disabled / cancelled） | 同 admin/login 79-88 | — |
| ④ role ∈ {super_admin, system_admin, org_admin} | 同 admin/login 91-94 | — |
| ⑤ org_admin 还要校验所属租户 `enabled` 且未过期 | 同 admin/login 97-109 | — |
| ⑥ 限流 | `checkLoginRate("elevate:" + userId)` | lib/rate-limit |

**JWT payload** 复用 admin/login 同款：
```ts
{ type: "admin", adminId: user.id, username: user.username ?? user.phone,
  role, tenantCode: role === "org_admin" ? user.tenant_code : null }
```

TTL 30 天，与 admin/login 完全一致。

**与 admin/login 的区别**：本接口**不需要密码** —— 用户态已经用密码登录过、user cookie
有效就证明身份；本接口只是"复用同一身份"翻一个 admin token 出来而已。

#### 3. 前端 · 顶栏右上角条件按钮

[`app/page.tsx`](../../app/page.tsx)：

- 加 `ShieldCheck` 图标 import
- 顶栏图标行（帮助 / 联系 / 设置 / 退出）里 contact 与 settings 之间插入按钮：
  ```tsx
  {user?.isAdmin && (
    <button onClick={enterAdmin} title="进入管理后台（新标签页）" aria-label="进入管理后台">
      <ShieldCheck size={20} />
    </button>
  )}
  ```
- **`user?.isAdmin && ...` 是渲染时判断 ——** 普通员工 DOM 里根本没这个按钮、F12
  也看不到。
- 新 `enterAdmin` 函数：
  ```ts
  await fetch("/api/auth/elevate-to-admin", { method: "POST" });
  window.open("/admin/dashboard", "_blank", "noopener,noreferrer");
  ```
- **必须先 await elevate 再 open** —— 否则新 tab 打开时 cookie 还没设上、middleware
  把它踢回登录页（实测踩过）。
- 失败弹错（`alert(error)`）：常见两种 —— "权限已被回收" / "组织已过期"。

### 边界与异常

| 场景 | 行为 |
|---|---|
| 用户中途被降权（role 改成 user）| `/api/me` 下次刷新返回 `isAdmin: false` → 按钮自动消失。如果用户没刷新还点了，elevate endpoint 重查 DB 也会拒绝（"该账号无后台访问权限"）|
| 组织被禁用 / 过期 | elevate 返回 403，弹"组织已被禁用/过期" |
| 已有 admin cookie 还点（重复 elevate）| 没问题，等于刷新 cookie；不需要先 check 是否已有 |
| 体验账号 / trial 用户 | `/api/me` 自身就拒 trial（403），所以 `isAdmin` 永远不会到达前端，按钮不会显示 |
| 同 IP 同账号被限流 | 后端 429 + "操作过于频繁，请 X 分钟后再试" |

### 没做的（按用户决策）

| 项 | 原因 |
|---|---|
| 按钮放在头像下拉里 | 用户选"顶栏独立按钮"，更显眼 |
| 仅 super/system_admin 可见，org_admin 不显 | 用户选"三种 admin 都能看到" |
| 短 TTL（2 小时） | 用户选"与 admin/login 同 30 天" |
| 按钮放在其它用户页（agents 详情 / settings / workflows）| 一期只在首页放；其它页面有自己的 header，留待后续按需扩 |
