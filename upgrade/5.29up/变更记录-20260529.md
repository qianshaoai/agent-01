## 背景

智能体搭建器「模型设置」分区原本是两步：先选模型供应商 select，再选模型名称 select。
admin 反馈"先选哪家厂商再选哪个模型"两层概念太绕——直觉应该是"我想用 gpt-4o-mini"
直接挑模型。本期把两个下拉合成一个，按供应商分组、选中后自动联动 provider_id +
model_params.model。

依赖：无 DB 迁移；改动仅前端 + test endpoint。

## P0 · Phase 1 · 模型选择合并下拉 + 自定义 popover

### 改动要点

1. `Provider` 类型补 `provider_code` 字段（API 实际返回，前端类型缺，分组标题与
   底部小字都要用）
2. 新增 `resolveProviderPresetForBuilder(provider)`——比全局 `inferPresetFromExisting`
   更严格：endpoint host 找不到时不回落到该 platform 第一个 preset，避免
   OpenAI 兼容自定义 endpoint 错套 GPT 推荐模型
3. 新增 `buildModelOptions(providers)`——把 providers × 各自 recommendedModels
   扁平化成 `[{ groupKey, groupLabel, optionValue, optionLabel }, ...]`
4. 新增 `composeValue(providers, provider_id, model)`——反推 select 当前值，老
   draft 兼容（model 在 preset 列表里 → 显示，不在 → 落自定义分支）
5. 替换原生 `<select>` 为自定义 `ModelSelectPopover` 组件：
   - 触发按钮 + 浮层 + ChevronDown 翻转动画
   - **固定可视高度 220px（约 5-6 行）+ 滚轮滑动**（用户决策 · 不用原生展开）
   - 分组标题 sticky，滚动时仍能看到当前在哪组
   - 选中项高亮 + ✓ icon
   - 点击外部 / Esc 关闭
6. select 下方加"当前供应商：name（provider_code）"小字（同模型名跨多 provider 必需）
7. `stripModelDesc` helper 去掉 preset label 末尾括号描述（"gpt-5.5（2026/04 旗舰）"
   → "gpt-5.5"）；分组标题里的括号保留（那是 provider_code）

### OpenAI 兼容（自定义）的特殊处理（用户决策）

原口径：custom endpoint 只显示「✏ 自定义模型名」。
新口径：openai 平台的 custom（典型场景：第三方中转）自动套 `openai-official` 的
recommendedModels，admin 仍能从下拉直接挑 GPT 模型。后续接正式 OpenAI 后这条
fallback 可去掉。

### 切换 provider 的 model 清空（5.29up Fix 4 / 小B R2）

切到不同 provider 的具体模型 → 写新 model；切到 `__custom__` → 显式清空旧 model。
**永远不带 A 的旧模型名到 B 上**（防上游 model not found）。

## P1 · Phase 2 · 自定义模型探针 + 保存前空值校验

### Phase 2.1 · 扩展 test endpoint 接受 `?model=` 覆盖

[`app/api/admin/model-providers/[id]/test/route.ts`](../../app/api/admin/model-providers/%5Bid%5D/test/route.ts)：

- 接受 query string `?model=xxx`，传则用它覆盖 provider 默认模型走探针
- 不传时行为完全不变（API 管理页的"测试"按钮零影响）
- 简单 sanitize：trim + 100 字符截断，防极端输入

### Phase 2.2 · 自定义模型名探针按钮

搭建器选「✏ 自定义模型名」时下方出现 `CustomModelProbeRow` 组件：

```
[ 自定义模型名（手填）] gpt-5.6   [ 测试该模型 ]
                                ✓ 连接成功（1234ms）
                          或    ✗ The model `gpt-5.6` does not exist
```

- 点击按钮 → POST 真打 `/api/admin/model-providers/:id/test?model=xxx`
- **必须读 `data.success` 不能只看 `res.ok`**（小B R2 教训：endpoint 失败时仍返
  HTTP 200 + `{ success: false, error }`）
- model 改变时清空旧结果（避免改了模型还看到旧的 ✓）
- 错误文本显示原始上游错误（如智谱"model not found"）方便排查

### Phase 2.3 · 保存/发布前空值校验

新加 `validateModelBeforeSave(draft)`：

- agent_type=external → 不校验
- chat 类型必须有 `provider_id` 与非空 `model`
- 失败 → toast 错误 + 阻断保存/发布

**仅手动保存与发布触发**（auto-save 跳过），让 admin 编辑期间不被打断。

防的场景：
- 选了豆包 / OpenAI 兼容自定义供应商但没填模型
- 上线后 chat 会兜底 `gpt-4o-mini`，非 OpenAI 厂商必 404
- 体感像智能体坏了

## P2 · 小B 复审 R5（4 项）· 验收阻断点收口

R4 之后 admin 实测，又抓出 4 个功能阻断：

### Fix 1 · 🔴 选「✏ 自定义模型名」仍会被反弹回默认模型（UI bug）

**问题**：onChange 把 model 清成 undefined 后，`composeValue` 看到空 model 又用
`provider.default_model` 反推具体模型。结果 DeepSeek / 智谱 / OpenAI 等默认模型在
推荐列表里的 provider，点自定义后输入框消失。

**修法**：
- `composeValue` **移除 default_model 兜底**，只信 draft 当下状态。
- 老 draft 兼容由新增的 `maybeSeedModelFromDefault(draft, providers)` 在**加载时
  一次性补齐**——把空 model 补成 provider.default_model（前提是默认在 preset 列表里）。

### Fix 2 · 🔴 保存/发布校验误拦"只依赖 provider 默认模型"的老草稿

**问题**：`validateModelBeforeSave` 只看 `draft.model_params.model`，不看
`provider.default_model`。老草稿写时只设了 provider 没设 model（runtime 走默认），
新校验会拦下。

**修法**：改成看 effective model = `draft.model || provider.default_model`，与
`chat/route.ts` runtime 同口径。

### Fix 3 · 🔴 publish route 缺空 effective model 兜底

**问题**：`publish/route.ts` 在 `provider.default_model` 也为空时仍继续发布，
没按方案返回 VALIDATION_ERROR。上线后 chat 兜底 gpt-4o-mini → 非 OpenAI 必 404。

**修法**：合并完 model_params 后检查 effective model；chat 类型 + effective 为空
→ 直接 `apiError("请先在「模型设置」选择具体模型；当前未填写、供应商也没有默认模型", "VALIDATION_ERROR")`。
与前端校验形成双保险。

### Fix 4 · 🔴 探针误报：上游中转 silently 回落到默认模型，填啥都 ✓

**问题**：admin 填了不存在的模型如 `got-9.0`（手误），相同 endpoint 实际是某第三方
中转，中转 silently 把请求路由到默认模型，返回 200 → 探针看到 200 报 ✓ 6000ms。
admin 误以为 got-9.0 可用，上线后炸。

**修法**：openai 平台 + 指定了 `?model=` 时，先 GET `{baseUrl}/models` 验证：
- 找到 → ✓ 通过，继续走 chat 探针
- 没找到 → ✗ 立即报「供应商接口里不存在模型「X」」
- /models 不可访问（404 / 网络错误 / 解析失败）→ 降级走 chat 探针（兼容不暴露 /models 的中转）

新加两个 helper `deriveModelsListUrl` / `checkModelInList`，5 秒超时。
API 管理页的"测试"按钮不传 `?model=`，行为完全不变。
