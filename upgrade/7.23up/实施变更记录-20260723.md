# 7.23up 实施变更记录（2026-07-23）

> 基线方案：`后台管理性能优化方案-20260723.md`  
> 原则：基线权限语义不再直接改写；新增需求、例外和偏差在本文件追加记录。

## 1. 本轮已完成

### 阶段 A：路由与可观测性基础

- middleware 将 `x-request-id` 写入下游请求头，同时保留响应 `X-Request-Id`。
- `withRequestLog()` 增加兜底 requestId、`Server-Timing`、状态码、总耗时和响应字节日志字段。
- Analytics、Dashboard Summary、Agent Center V2 路由接入统一请求日志 wrapper。
- `.env.local.example` 增加三个默认关闭的 V2 开关：
  - `NEXT_PUBLIC_ADMIN_DASHBOARD_SUMMARY_V2=false`
  - `ADMIN_ANALYTICS_SQL_AGG=false`
  - `ADMIN_AGENT_CENTER_V2=false`

### 阶段 B：持久化后台 Shell

- `/admin` 登录/首次改密页保留在路由组外。
- 全部后台业务页面迁入 `app/admin/(console)/**`，公开 URL 不变。
- 新增持久化 `(console)/layout.tsx`、`AdminShell` 和 `AdminSessionProvider`。
- 原 `AdminLayout` 收敛为只负责内容区的 `AdminPageFrame` 兼容层，不再创建侧栏或请求公共状态。
- `/api/admin/me` 已收敛为 `AdminSessionProvider` 唯一调用；`useAdminPermissions()` 和页面级角色判断改读 Context。
- Session 状态覆盖：
  - 401：清空上下文并返回 `/admin`；
  - 403：显示无权状态；
  - 首次 5xx：显示可重试错误；
  - 已有成功上下文时 5xx：保留旧上下文并提示；
  - focus/manual refresh 使用 single-flight 和请求序号保护。
- custom admin 直接访问 Dashboard 时跳转工作流页面。

### 阶段 C：Analytics、Dashboard 与 Effective Scope

- `migration_v57_agent_effective_admin_scopes.sql`
  - 使用 `SECURITY INVOKER` view；
  - 只有完全不存在任何 `resource_permissions` 行时才回退；
  - 创建者组织使用 `COALESCE(admin.tenant_code, user.tenant_code)`；
  - 仅 `service_role` 可查询。
- 单条和批量草稿 owner resolver 已统一为相同的 nullish fallback。
- `migration_v58_admin_analytics_rpc.sql`
  - 新增 `admin_usage_summary`；
  - 新增 `admin_user_usage_page`；
  - 新增 `admin_visible_agent_count`；
  - 全部撤销浏览器角色执行权，仅授权 `service_role`。
- Analytics V2：
  - summary/users 拆分；
  - 用户 Tab 懒加载；
  - 用户搜索 400ms 防抖；
  - 旧请求可取消；
  - 用户维度数据库分页；
  - V2 默认关闭，保留旧实现回滚。
- Dashboard Summary V2：
  - builtin-only；
  - 每项指标独立鉴权，无权返回 `null`；
  - 组织范围 `totalAgents` 通过 Effective Scope 统计；
  - 30 秒短缓存包含 actor、角色、权限指纹和完整 scope；
  - V2 默认关闭。

### 阶段 D：Agent Center V2

- `migration_v59_admin_agent_center_rpc.sql`
  - 数据库先按权限过滤，再筛选、统计和分页；
  - 多 scope 使用“无任何越界 scope”的 AND 语义；
  - `.all` 是唯一范围绕过路径；
  - dept/team 反查失败按越界处理；
  - 空 effective scope 保留现有行为；
  - 列表、total、状态和分类统计复用同一个可见集；
  - 当前页引用、会话数和动作权限在 SQL 批量计算；
  - 仅 `service_role` 可执行。
- API 保留原 Node.js 路径；`ADMIN_AGENT_CENTER_V2=true` 时才调用新 RPC。

## 4. 验收整改补充

- Session loading/首次 5xx 不再挂载业务页面；401、403、stale 5xx 分离，卸载时中止 `/api/admin/me`。
- Analytics 自动加载和手动刷新统一使用 AbortController + request sequence，旧响应不能覆盖新状态。
- 关键接口日志增加 actor source/role、auth/business/serialize/total 分段耗时和响应字节。
- 新增 `/api/admin/org-tree?purpose=picker`；Analytics、用户、工作流、智能体中心、日志和旧智能体页共享 5 分钟 single-flight 参考数据缓存。
- 操作日志翻页只刷新日志列表；组织管理通过聚合组织树一次取得部门和团队，修改后主动失效缓存。
- `requireAdminActor()` 改为统一上下文解析：JWT 验签后只读取一次管理员/用户主资料，再加载权限；后台页面 Middleware 不再重复执行 freshness 数据库查询，业务 API 仍保留完整实时校验。
- Dashboard Summary 在 Effective Scope/Analytics RPC 未就绪时只将相应指标降级为 `null`，不会用普通总数替代，也不会拖垮其它摘要指标。
- 已提供并发索引脚本、前后执行计划模板、数据库授权/索引验收脚本和 10/50/100 并发压测脚本。

## 6. 全量复审整改

- 修复组织树越权：`org_admin` 是硬组织边界，即使持有 `tenant.read.all` 或完整层级 all 权限也只能返回本组织；system/custom 必须同时持有 `tenant/dept/team.read.all` 才能读取全平台组织树，任意业务资源 `*.read.all` 不再升级组织树权限。
- Analytics legacy 分支兼容 `view=summary/users`；摘要请求不再加载用户日志，用户请求返回真实 `page/pageSize/total`，无 `view` 的旧调用仍保留组合响应。
- 请求日志不再通过 `res.clone().arrayBuffer()` 复制响应体；只记录已有 `content-length`，精确响应字节改由压测客户端统计。
- `admin_table` 和 `user_admin` 的 builtin org admin 在登录及每次业务鉴权时统一检查组织 enabled/expires_at。
- 新增真实数据库等价门禁：逐行比较 TypeScript resolver 预期与 `agent_effective_admin_scopes`，校验边界夹具覆盖，并逐组织对比 `admin_visible_agent_count` 的 AND/fail-closed 结果。
- 压测启动前通过受保护 readiness 接口确认三个 V2 Flag 全开；百分位按“并发级别 + 单接口”分别计算，并记录响应字节、数据库连接/等待/锁、Node 内存和外部数据库 CPU 证据。
- 索引验收改为执行计划驱动：三个索引均需明确 `create/not_required`，只有决定创建的索引才要求存在且有效。
