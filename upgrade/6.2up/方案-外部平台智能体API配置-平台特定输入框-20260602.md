## R0 小B审核记录（R1 已收口）

R0 结论：方向成立，但当时不建议直接开工。R1 已把下面 5 个问题收口到正文，并更新状态为“可进入实施”：

1. **术语要改**：本期不是 `agent_type="external"` 的「外链跳转型」，而是 Coze / Dify / 元器 / 清言这类「外部平台智能体 API」的参数输入框。标题和正文避免再写「外链型」，防止和 `external_url` 功能混淆。
2. **schema 不能只按 `agent.platform` 判断**：当前 API 配置下拉只按 `category=agent|model` 拉 provider，后端也只校验 category；运行时真正调用会使用所选 provider 的 `platform`。R1 已明确 `effectivePlatform = selectedProvider?.platform ?? agent.provider?.platform ?? agent.platform`，并定义 provider 切换时如何保留/重分配已填参数。
3. **平台 key 必须用仓库真实值**：当前没有 `openai-compatible` 这个入库 platform；大模型 provider 使用 `openai | zhipu | anthropic`，agent 表单还有 `other`。R1 的 schema 示例要按这些真实 key 写，`openai-compatible` 只能作为说明文案，不能作为主分支。
4. **保存前校验要补完整**：高级 JSON 必须校验为 plain object；JSON 解析失败、数组/null、数字 NaN、越界值都要 toast 后阻止保存。当前旧逻辑会吞掉 JSON parse error，本期应顺手修掉，不要继承。
5. **分支建议独立**：6.2up 是功能体验改造，和 6.1up responsive 无直接关系。除非明确要捆绑发版，否则建议从当前代码切 `feature/6.2up-platform-input` 独立提交，避免被 6.1up 剩余响应式工作卡住。

可保留的决策倾向：Dify 条件隐藏 JSON 折叠、input 优先、JSON 默认收起、schema 放 `lib/platform-param-schema.ts` 都合理。

### R1-4 · 保存前校验补完整

R0 C3 保存片段只校验 `required`，按小B 第 4 条补完：

```ts
function parseAdvancedJson(raw: string): { ok: true; value: Record<string, unknown> } | { ok: false; msg: string } {
  const t = raw.trim();
  if (!t) return { ok: true, value: {} };
  let parsed: unknown;
  try { parsed = JSON.parse(t); }
  catch (e) { return { ok: false, msg: `高级 JSON 解析失败：${(e as Error).message}` }; }
  if (parsed === null || typeof parsed !== "object" || Array.isArray(parsed)) {
    return { ok: false, msg: "高级 JSON 必须是对象 {...}，不能是 null / 数组 / 标量" };
  }
  return { ok: true, value: parsed as Record<string, unknown> };
}

function validateNumberField(f: ParamField, raw: string): { ok: true; value: number } | { ok: false; msg: string } {
  if (raw === "") return { ok: true, value: NaN };  // 留空走平台默认（NaN 会被外层过滤）
  const n = Number(raw);
  if (!Number.isFinite(n)) return { ok: false, msg: `「${f.label}」必须是数字` };
  if (f.min !== undefined && n < f.min) return { ok: false, msg: `「${f.label}」不能小于 ${f.min}` };
  if (f.max !== undefined && n > f.max) return { ok: false, msg: `「${f.label}」不能大于 ${f.max}` };
  return { ok: true, value: n };
}

async function handleSaveApi() {
  // 1. 解析高级 JSON
  const adv = parseAdvancedJson(apiForm.advancedJson);
  if (!adv.ok) { toast(adv.msg); return; }

  // 2. 解析 input 字段
  const inputParams: Record<string, unknown> = {};
  for (const f of schema.fields) {
    const raw = apiForm.inputs[f.key] ?? "";
    if (f.type === "number") {
      const r = validateNumberField(f, raw);
      if (!r.ok) { toast(r.msg); return; }
      if (Number.isFinite(r.value)) inputParams[f.key] = r.value;
    } else {
      if (raw !== "") inputParams[f.key] = raw;
    }
  }

  // 3. required 校验
  for (const f of schema.fields) {
    if (f.required && (inputParams[f.key] === undefined || inputParams[f.key] === "")) {
      toast(`「${f.label}」必填`);
      return;
    }
  }

  // 4. input 覆盖 advancedJson 同 key（R1-input 优先）
  const finalParams = { ...adv.value, ...inputParams };

  // 5. 提交
  await fetch(...);
}
```

**关键点**：

- 高级 JSON 必须是 `Record<string, unknown>`，array / null / 标量都阻塞；
- number 字段：`""` → 留空（不传），其它非数字 → 阻塞；
- input 优先级高于 advancedJson 同 key（决策点 2 推荐 A）；
- 错误信息含字段 label，方便 admin 定位。

export type ParamField = {
  key: string;           // JSON key，如 "bot_id"
  label: string;         // UI 显示，如 "Bot ID"
  type: "text" | "number" | "password";
  required?: boolean;
  placeholder?: string;
  hint?: string;         // 字段下方小字提示
  min?: number;          // type=number 时
  max?: number;
  step?: number;
};

export type PlatformSchema = {
  fields: ParamField[];
  noFieldsHint?: string;  // 字段为空时显示的引导（如 dify）
};

export function schemaForPlatform(platform: string): PlatformSchema {
  switch (platform) {
    case "coze":
      return { fields: [{
        key: "bot_id", label: "Bot ID", type: "text", required: true,

    case "yuanqi":
      return { fields: [{
        key: "assistant_id", label: "Assistant ID", type: "text", required: true,
        placeholder: "如 abc-xxx", hint: "在腾讯元器后台智能体详情页复制",

    case "qingyan":
      return { fields: [
        { key: "assistant_id", label: "Assistant ID", type: "text", required: true,

### C3 · 数据流（加载 / 编辑 / 保存）

**加载**（openApi 时）：

```ts
// 当前老逻辑（line 178-184 推测）
const modelParamsJson = JSON.stringify(agent.model_params ?? {}, null, 2);
setApiForm({ providerId: agent.provider_id ?? "", modelParams: modelParamsJson });

// 改造后
const params = agent.model_params ?? {};
const providerId = agent.provider_id ?? "";
const selectedProvider = apiProviders.find(p => p.id === providerId);
const effectivePlatform = selectedProvider?.platform ?? agent.provider?.platform ?? agent.platform;
const schema = schemaForPlatform(effectivePlatform);
const inputValues: Record<string, string> = {};
const extraKeys: Record<string, unknown> = {};
const schemaKeys = new Set(schema.fields.map(f => f.key));
for (const [k, v] of Object.entries(params)) {
  if (schemaKeys.has(k)) inputValues[k] = String(v);
  else extraKeys[k] = v;
}
setApiForm({
  providerId,
  inputs: inputValues,      // 填进 input 框
  advancedJson: Object.keys(extraKeys).length > 0
    ? JSON.stringify(extraKeys, null, 2)
    : "",                    // 只放 schema 之外的 key
});
```

**保存**（handleSaveApi）：

```ts
// 合并 input 值 + 高级 JSON；完整校验见 R1-4 的 parseAdvancedJson / validateNumberField
const adv = parseAdvancedJson(apiForm.advancedJson);
if (!adv.ok) { toast(adv.msg); return; }
const inputParams: Record<string, unknown> = {};
for (const f of schema.fields) {
  const raw = apiForm.inputs[f.key] ?? "";
  if (f.type === "number") {
    const r = validateNumberField(f, raw);
    if (!r.ok) { toast(r.msg); return; }
    if (Number.isFinite(r.value)) inputParams[f.key] = r.value;
  } else if (raw !== "") {
    inputParams[f.key] = raw;
  }
}
// input 字段优先覆盖（避免歧义）
const finalParams = { ...adv.value, ...inputParams };
// 校验必填
for (const f of schema.fields) {
  if (f.required && !inputParams[f.key]) {
    toast(`「${f.label}」必填`);
    return;
  }
}
// 提交
await fetch(..., { body: JSON.stringify({ providerId: apiForm.providerId, modelParams: finalParams }) });
```

## F · 决策点（R1 已拍板）

### 决策点 0 · schema 依据哪个 platform

| 选项 | 描述 |
|---|---|
| **A · 所选 provider.platform 优先**（推荐） | `effectivePlatform = selectedProvider?.platform ?? agent.provider?.platform ?? agent.platform`，不改现有 category 级绑定规则 |
| B · 强制 provider.platform 与 agent.platform 一致 | 下拉和后端都改为精确平台校验，范围更大 |

R0 审核建议走 A：本期只优化输入体验，不扩大后端绑定规则改造。

### 决策点 1 · dify 平台显示什么

| 选项 | 描述 |
|---|---|
| **A · 显示提示 + 条件隐藏 JSON 折叠**（推荐） | 「Dify 无需额外配置」；`advancedJson` 为空时隐藏 JSON，非空时显示折叠以承载旧参数 |
| B · 显示提示 + 保留 JSON 折叠 | 提示 + 折叠仍可点开 |
| C · 完全隐藏整段 modelParams | 弹窗只剩「命名 API」+ 保存按钮 |

### 决策点 2 · input 值 vs JSON 冲突时谁优先

| 选项 | 描述 |
|---|---|
| **A · input 优先**（推荐） | 如果 input 填了 bot_id，JSON 即使写 bot_id 也被覆盖 |
| B · JSON 优先 | input 是默认值、JSON 可覆盖 |

A 更直观（用户看到 input 就预期 input 值生效）。

### 决策点 3 · JSON 折叠默认状态

| 选项 | 描述 |
|---|---|
| **A · 默认收起**（推荐） | 普通 admin 看不到 JSON、降低认知负担；进阶 admin 主动展开 |
| B · 默认展开 | 老 admin 习惯沿用 |

### 决策点 4 · ParamField schema 文件位置

| 选项 | 描述 |
|---|---|
| **A · `lib/platform-param-schema.ts`**（推荐） | 与 adapter / preset 同层，便于复用 |
| B · `lib/model-providers/platform-schema.ts` | 跟 preset 同文件夹 |
| C · `components/admin/api-config-modal.ts` 文件内 | 字段定义跟 UI 强耦合 |
