### 用户实测痛点 + 1366 专项口径（R1 补强 · 小B 评审点 2）

仅 **小屏 1366×768 控件拥挤 / 截断**，其它三档用户未感知，不在本期。

**关键诊断 · 1366 不能只靠 `lg` breakpoint 区分**：

- Tailwind 默认 `lg = 1024px`，1366 / 1440 / 1920 都会命中 `lg:` → `lg:` 只能区分 `<1024` 与 `>=1024`，**不能表达 1366 专项**
- [`components/layout/admin-layout.tsx:223`](../../components/layout/admin-layout.tsx) 侧栏 `w-60` = 240px，`hidden lg:flex` 在 1366 上显示
- 1366 实际**内容区可用宽度** = 1366 − 240（侧栏）− 32（左右 padding）− 32（内边距）≈ **~1062px**
- [`app/admin/agent-builder/[id]/page.tsx:852`](../../app/admin/agent-builder/[id]/page.tsx) `grid-cols-[1fr_400px]` 右栏占 400px → 左主栏只剩 **~640px** → 表单挤
- **结论**：1366 需要专门的 `lg:max-[1439px]:` 或 token media query 区间策略（C2 节展开），不是单纯 `lg:` 能解决

## C · 设计 · 4 层策略

### C1 · 在现有 token 体系上扩展容器响应式 token（R1 修正）

**已有 token 不动**（A 节列的字号 / 圆角 / 阴影 / 颜色 / 字号缩放体系）。本期只**新增**容器/分辨率响应式相关 token：

| 类目 | 新增变量 | 1366×768 | 1920×1080 | 2560×1440 | 说明 |
|---|---|---|---|---|---|
| 侧栏宽 | `--sidebar-w` | 200px | 240px | 260px | admin 侧栏按视口宽响应 |
| 内容区 max | `--content-max-w` | none | 1600px | 1900px | 主内容容器宽度上限 |
| 主内边距 | `--page-px` | 16px | 24px | 32px | 页面左右内边距 |
| 卡片间距 | `--gap-card` | 12px | 16px | 20px | 卡片网格 / 列表间距 |
| 表格 dense 阈值 | `--table-dense` | 1 | 0 | 0 | 1366 下表格紧凑模式开关 |

实现方式：CSS variables + media query 覆盖（按 globals.css 5.7up/5.9up 既有写法）。

```css
:root {
  --sidebar-w: 240px;
  --content-max-w: 1600px;
  --page-px: 24px;
  --gap-card: 16px;
}
@media (max-width: 1439px) {  /* 1366 段（1024-1439px；1440 不含，归 default 段）*/
  :root {
    --sidebar-w: 200px;
    --content-max-w: none;
    --page-px: 16px;
    --gap-card: 12px;
  }
}
@media (min-width: 1920px) {  /* 2K+ */
  :root {
    --sidebar-w: 260px;
    --content-max-w: 1900px;
    --page-px: 32px;
    --gap-card: 20px;
  }
}
```

具体阈值 + 是否走 Tailwind v4 `@theme` 还是纯 CSS variables 在小B 三审确认（G 节决策点 1）。

### C2 · 容器与栅格策略（R1 修正 · 1366 专项）

**1366 专项断点策略**（核心修正，小B 评审点 2）：

- 1366 / 1440 / 1920 都会命中 `lg:`，单纯 `lg:` 不能表达 1366 专项 → 必须用 **`lg:max-[1439px]:`**（1024-1439px 区间）或 token media query 作为 1366 段
- 表格列优先级隐藏改成 **`max-[1439px]:hidden`**（1366 段隐藏次要列）而非 `hidden lg:table-cell`
- admin 侧栏在 1024-1439 段窄到 200px（用 `--sidebar-w` token，C1 已定义），1440+ 段恢复 240/260px

**admin 侧栏 + 主内容偏移整体改造**（R1.1 修正 · 小B 二审 #1 + #2）：

R1 只改了 [`admin-layout.tsx:223`](../../components/layout/admin-layout.tsx) 侧栏宽度，**漏了 [line 241](../../components/layout/admin-layout.tsx) 主内容 `lg:ml-60` 固定 240px 偏移**——侧栏变 200/260 后主内容仍按 240 偏移 → 1366 段产生 40px 空隙、2K 段产生 20px 重叠。R1.1 必须同步改主内容偏移。

**推荐方案 · CSS variable 同步**（不用 Tailwind 任意值类避免 specificity 坑）：

```diff
- <aside className="hidden lg:flex flex-col w-60 ...">
+ <aside
+   className="hidden lg:flex flex-col ..."
+   style={{ width: 'var(--sidebar-w)' }}
+ >

- <div className="flex-1 lg:ml-60 flex flex-col min-h-screen">
+ <div className="flex-1 flex flex-col min-h-screen lg:[margin-left:var(--sidebar-w)]">
```

注：原 `lg:ml-60` 的 lg gate（< 1024 隐藏侧栏 → 主内容无偏移）必须保留。这里用 Tailwind v4 任意属性语法 `lg:[margin-left:var(--xxx)]`，避免 inline style 在 `<1024` 时也生效。

**更彻底方案 · 后台 shell 改 grid 布局**（R1.1 备选，工程量略大）：

```tsx
<div className="lg:grid lg:grid-cols-[var(--sidebar-w)_1fr] min-h-screen">
  <aside>...</aside>
  <main>...</main>
</div>
```

侧栏宽度变化时 main 自动跟随，根本不存在偏移漏改的可能。这是更"对的"做法，但需要 admin-layout.tsx 较大改造、其它页面绕过 main 容器的特殊布局（如 dashboard）要回归测。

→ **R1.1 默认走 CSS variable 同步**（简单、改 2 行），grid 改造作为后续优化项。

**根 layout 容器**：

- 全宽 + 内部 `max-w-[var(--content-max-w)]` 居中（1366 段 none = 全宽利用；1440+ 段定宽居中）
- 主页面 padding 用 `px-[var(--page-px)]`（1366 = 16px；1920+ = 24-32px）

**flex 内容区**：统一加 `min-w-0` 防 flex 子项撑爆（已是 5.27up 之后惯例，但旧页面要补）

**表格策略**（model-providers 等表格页 R1 增补）：

- 表格容器**必须** `overflow-x-auto`（[`app/admin/model-providers/page.tsx:452`](../../app/admin/model-providers/page.tsx) 现在是 `overflow-hidden` → 改）
- 次要列（如「编号」「归属」「最后修改时间」）在 1366 段隐藏：`max-[1439px]:hidden`
- 操作列在 1366 段折叠成「⋯」下拉（避免 4 个图标横排顶出）

**通用 PageHeader 改造**（[`components/ui/page-header.tsx:30`](../../components/ui/page-header.tsx)，R1 新增 · 小B 中优 #3）：

- actions 区 `shrink-0` + 无 wrap → 1366 上挤爆 title
- 改成 `flex-wrap gap-2`（actions 多时换行到下一行），或加 `max-[1439px]:flex-col` 主动堆叠

### C3 · 硬编码替换策略 · 四类（R1 修正 · 小B 评审点 3）

R0 三类不够，**R1 新增 D 类 · layout 容器模式**（覆盖小B 点名的 grid-cols / w-N / max-w-Xxl / h-screen / 内联 calc）：

- **A 类 · responsive prefix**（最常见）：
  ```diff
  - className="w-[260px]"
  + className="lg:max-[1439px]:w-[200px] min-[1440px]:w-[240px] min-[1920px]:w-[260px]"
  ```
  **R1.1 修正**（小B 二审 #3）：用 `min-[A]:` + `lg:max-[B]:` 范围明确区间，避免 `max-[1439px]:w-[200px] lg:w-[260px]` 在 1366 上**两条都命中**导致最终值不直观（后者覆盖前者，1366 实际是 260px 而不是预期的 200px）。或者直接走 CSS variable + style，绕开 specificity。
- **B 类 · clamp() 流式**（chat 气泡 / modal 等动态尺寸）：
  ```diff
  - className="min-w-[360px]"
  + className="min-w-[clamp(280px,30vw,360px)]"
  ```
- **C 类 · token 引用**（spacing / radius / font，复用 globals.css 现有 + C1 新增 token）：
  ```diff
  - className="px-4 py-3 rounded-[16px]"
  + className="px-[var(--page-px)] py-3 rounded-[var(--radius-lg)]"
  ```
- **D 类 · layout 容器模式**（R1 新增，含小B 点名 5 种模式）：

  | 模式 | 例子 | 改造方向 |
  |---|---|---|
  | `grid-cols-[1fr_400px]` | agent-builder 双栏 | `lg:grid-cols-[1fr_360px] 2xl:grid-cols-[1fr_440px]` 或换 `[1fr_var(--side-panel-w)]` |
  | `w-60/w-64`（文字数字宽度类） | sidebar / 列表项 | 改 `var(--sidebar-w)` 或加 responsive prefix |
  | `max-w-6xl` / `max-w-[1600px]` | 主容器宽度上限 | 改 `max-w-[var(--content-max-w)]` |
  | `h-screen` / `min-h-screen` | 全屏布局容器 | 加 `min-h-[100dvh]` fallback（防移动浏览器地址栏遮挡，桌面无副作用） |
  | `lg:-ml-16` 负 margin / 内联 `calc(100vh - 120px)` | 特殊定位 | 逐个 case 评估，可能要换 grid / flex |

## G · 待小B 审的 3 决策点（R1.1 修正 · 删 2 + 加 1 后剩 1/2/5）

### 决策点 1 · Design tokens 实现方式

- **选项 A · CSS variables**（推荐）：globals.css 加 `:root` + `@media (max-width:1440px)` 改写。优点：兼容性最广、可在任意 className 用 `var()`；缺点：Tailwind autocomplete 不识别。

- 选项 C · 混合：tokens 用 CSS variables 定义，Tailwind v4 `@theme` 仅做 alias 引用。优点：两边都享；缺点：维护两套。

### 决策点 2 · Codemod 自动 apply 风险

- **选项 A · 仅出报告**（推荐）：人工审 + 手动 apply。安全。慢。

→ R1.1 默认 A，若小B 倾向加速可改 C。
