# 7.28up 智能体与工作流分页性能优化实施变更记录

日期：2026-07-28  
状态：代码已实现，数据库迁移与环境开关尚未在目标环境执行

## 1. 本次已实现

### 1.1 绑定智能体安全边界

- 新增 `lib/agent-binding-access.ts`，批量计算当前 actor 可读的智能体摘要。
- 工作流步骤 POST、PATCH 在写入 `agent_id` 前重新校验 `agent.read`。
- 不存在和无权读取统一返回 404，避免通过 403/404 探测资源。
- 工作流列表只返回当前 actor 可读的 `step.agent` 最小摘要：
  - `id`
  - `agent_code`
  - `name`
  - `platform`
  - `agent_type`
  - `published_from_draft_id`
- 不返回 `external_url`。
- 部门、小组归属批量查询，避免当前页步骤逐条鉴权形成 N+1。
- 修复步骤 PATCH 只传 `agentId` 时可能被错误清空的旧逻辑。

### 1.2 版本化智能体 Picker

- 新增 `GET /api/admin/agents/picker/page`，响应契约固定为 v2：

  ```json
  {
    "contractVersion": 2,
    "data": [],
    "pagination": {
      "page": 1,
      "pageSize": 20,
      "total": 0
    }
  }
  ```

- 支持服务端 `q/page/pageSize`，`pageSize` 最大 50。
- 固定按 `name ASC, id ASC` 排序。
- 原 `/api/admin/agents/picker` 未修改，旧浏览器标签页继续使用旧契约。
- `ADMIN_AGENT_PICKER_V2=false` 时，新路径使用兼容回退实现；迁移完成后开启开关走 v60 RPC。
- 工作流页面不再首屏拉取旧 Picker；仅打开绑定弹窗时分页加载，搜索 250ms 防抖，并取消过期请求。

### 1.3 工作流当前页收窄

- 旧路径的权限摘要查询已从全部 `resource_permissions` 改为只查当前页工作流 ID。
- 当前页绑定智能体摘要按权限过滤。
- 工作流页面主请求增加 `AbortController` 和最新请求序号，旧请求不能覆盖新筛选结果。
- 标签请求与主列表解耦，不再阻塞主 loading。
- 组织树改为打开新增/编辑工作流弹窗时按需加载。

### 1.4 v60 / v61 数据库分页

- `migration_v60_admin_agent_picker_rpc.sql`
  - 智能体权限可见性、搜索、准确总数和分页在 SQL 内完成。
  - `SECURITY INVOKER`。
  - 仅 `service_role` 可执行。

- `migration_v61_admin_workflow_page_rpc.sql`
  - 工作流权限可见性在 SQL 内完成，不向 Node.js 返回全量可见 ID。
  - `stats_base` 与 `page_base` 分离。
  - 标签名称参与关键词搜索。
  - 分类总数、未分类总数、准确分页总数在 SQL 内聚合。
  - `focusId` 使用 `row_number()` 定位。
  - `sort_order ASC, id ASC` 稳定排序。
  - 请求页超过有效页时自动回到最后一页，覆盖删除当前页最后一条场景。
  - `custom:org/dept/team` 语义已固化。
  - `SECURITY INVOKER`，业务表全部使用 `public.` 限定。
  - 撤销 `PUBLIC/anon/authenticated` 执行权，仅授权 `service_role`。

### 1.5 灰度与验收

- 新增环境开关：
  - `ADMIN_AGENT_PICKER_V2`
  - `ADMIN_WORKFLOW_PAGE_V2`
- `/api/admin/performance-readiness` 已返回上述开关状态。
- 新增：
  - `scripts/check-7.28up-migrations.ts`
  - `scripts/verify-7.28up-db.ts`
  - `scripts/verify-7.28up-equivalence.ts`

  - 超出旧上限：只使用独立 SQL 结果或预置 fixture 作为 oracle，明确不以旧接口为准。

## 3. 上线顺序

1. 在预生产执行 v57（若未执行）、v60、v61。
2. 执行 `npm run verify:7.28up:db`。
3. 准备上限内数据集和超限 fixture，执行 `npm run verify:7.28up:equivalence`。
4. 根据 `EXPLAIN (ANALYZE, BUFFERS)` 决定是否执行候选索引，索引必须单独、非事务执行。
5. 先开启 `ADMIN_AGENT_PICKER_V2=true`，观察错误率和 P95/P99。
6. 再开启 `ADMIN_WORKFLOW_PAGE_V2=true`，复验不同角色和筛选组合。
7. 执行 `npm run loadtest:7.28up`，保存分阶段、冷热缓存、搜索/翻页比例和响应大小结果。
8. 灰度稳定后再扩大流量。

## 4. 回滚

- 设置 `ADMIN_WORKFLOW_PAGE_V2=false`：工作流列表回到旧查询路径，但保留当前页权限摘要收窄和前端请求拆分。
- 设置 `ADMIN_AGENT_PICKER_V2=false`：版本化 Picker 使用兼容回退实现；旧 `/picker` 契约不受影响。
- 数据库函数和候选索引可以保留，不需要在紧急回滚中删除。
