## 1. 改动 · §1.2 Key 空间拆分（P0-1 收口）

**R1.0 删 `// 6.4up 原 12 keys（custom 通道独占）` 这条注释**——它就是矛盾源头。改为：

```ts
// lib/permission-keys/workflow.ts
//   6.4up 原 12 keys —— custom 通道（requirePermission）写入校验用
//   注意：这些 keys **也存在于** ADMIN_PERMISSION_KEYS（让 builtin admin 也能被 super 配 workflow 权限）
//   两通道独占的是「写入校验」而非 key 本身
export const WORKFLOW_PERMISSION_KEYS = [
  "workflow.read.team", ..., "workflow.update.all"  // 共 12 个
] as const;

// lib/permission-keys/admin.ts
//   ADMIN 通道（v2 builtin admin override）的全集
//   workflow.read/create/update.{team,dept,org,all} 12 个与 WORKFLOW set 重叠
//   workflow.enable/duplicate/delete.* 是 R1.1 新增，只在 ADMIN set
export const ADMIN_PERMISSION_KEYS = [
  // ... workflow 12 个重叠 + workflow.enable/duplicate/delete.* 新增
  // ... agent 系列、agent_draft 系列、kb 系列、provider 系列等
] as const;
```

**写入校验分流**（保持 R1.0）：
- `custom-roles` POST/PATCH → 严校 `WORKFLOW_PERMISSION_KEYS`（custom admin 只能配工作流）
- `admin-overrides` POST/PATCH → 严校 `ADMIN_PERMISSION_KEYS`（super 配 builtin admin 时全集）

**双通道隔离硬规则**（R1.0 保留）：
- `requireAdmin()` 通道不读 `user_custom_roles` —— 哪怕该 user 之前有 workflow custom role，晋升 builtin admin 后不生效
- `requirePermission()` 通道不读 v52 两表 —— 6.4up 行为零破坏

## 4. 改动 · §1.5 Adapter 接口异步化（P1-2 收口）

R1.0 adapter interface：
```ts
checkRead(actor, row): boolean;             // ← 同步，错
checkWrite(actor, row, action): boolean;    // ← 同步，错
```

**R1.1 全部异步化 + 增加预加载入参**：

```ts
// lib/access-facade.ts
export interface ResourceAccessAdapter<TRow = unknown> {
  resourceKind: string;
  listFilter(actor: PermissionActor): QueryModifier | null;
  loadDetail(id: string): Promise<TRow | null>;
  checkRead(actor: PermissionActor, row: TRow): Promise<boolean>;        // ← async
  checkWrite(actor: PermissionActor, row: TRow, action: string): Promise<boolean>;  // ← async
  resolveCreateOwnership(actor: PermissionActor, payload: Partial<TRow>): Partial<TRow>;
}

// requireAccess 接收 row（已 load）或 id（自动 load）
export async function requireAccess(
  actor: PermissionActor,
  resourceKind: string,
  action: string,
  opts?: { row?: unknown; id?: string },
): Promise<Response | null>;
// 实现逻辑：
//   if (opts.row) → 直接调 adapter.checkRead/checkWrite(actor, opts.row, action)
//   else if (opts.id) → adapter.loadDetail(opts.id) → 404 屏蔽 / 调 check
//   else → 视为 'create' / list 场景，不需要 row
```

**路由模板更新**（R1.1 推荐写法）：

```ts
// 已有路由已经 load 过 row（如 5.30up KB PATCH）→ 复用，零重复查询：
const existing = await db.from("knowledge_bases").select(...).eq("id", id).maybeSingle();
if (!existing) return apiError("不存在", "NOT_FOUND");

const accessErr = await requireAccess(actor, "knowledge_base", "update", { row: existing });
if (accessErr) return accessErr;

// 全新接入的路由（自己懒得 load）→ 让 facade 帮 load：
const accessErr = await requireAccess(actor, "category", "delete", { id });
if (accessErr) return accessErr;
```

**adapter 内部** workflow / agent / user 那种"scope 判断要查 DB"的情况：直接在 `checkWrite` 里 `await db.from("resource_permissions").select(...)`，再也不假装同步了。

> #22. ✅ super 在 Tab 2 把 `system_admin` 默认包里 `workflow.enable.all` 删掉 → 所有 system_admin 立即不能启停工作流；但仍能创建/读/改（保持 6.4up 行为不变）
