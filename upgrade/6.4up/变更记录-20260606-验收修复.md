## 条目 1 · 自定义角色编辑弹窗：资源名英文 → 中文

**现象（用户验收）**
「新建 / 编辑自定义角色」弹窗里，权限分块的标题显示英文 `Workflow / Agent / Agent_draft`，不美观。

**根因**
[`components/permissions/v2/tab-custom-roles.tsx`](../../components/permissions/v2/tab-custom-roles.tsx) 的 `RoleEditModal` 直接渲染原始 resource key（`{resource}`）再用 CSS `capitalize` 首字母大写，所以 `agent_draft` → `Agent_draft`。
而 sibling 组件 [`permission-matrix.tsx`](../../components/permissions/v2/permission-matrix.tsx) 早已导出一份完整中文映射 `RESOURCE_LABEL`（工作流 / 智能体（已发布）/ 智能体（草稿）/ 知识库 / API 管理 / 公告 / 用户 / 组织 / 分类 / 部门 / 小组 / 审计），此弹窗未复用。

**修复**
| 文件 | 改动 |
|---|---|
| `components/permissions/v2/tab-custom-roles.tsx` | ① `import { RESOURCE_LABEL } from "./permission-matrix"`；② 分块标题改为 `{RESOURCE_LABEL[resource] ?? resource}`，去掉 `capitalize`，并按 matrix 视图同款样式在中文名右侧补一个灰色 mono 的原始 key 标注（两个视图统一）。 |

未映射的资源仍回退原始 key（兜底不丢信息）。

**CI** `npx tsc --noEmit` ✅ 0 error。

**未验证** 弹窗在登录态后台内，视觉确认需 admin 登录后实测（验收时一并看）。

## 条目 2 · 自定义角色（custom_admin）进入后台崩溃 / 落地页错配

**现象（用户验收）**
自定义角色登录后台后，`/admin/dashboard` 整页「页面出错了 · Cannot read properties of undefined (reading 'length')」，Console 一片 `/api/admin/{analytics,agents,notices,users}` 401。

**根因（两层独立问题）**
- **A · 落地页错配**：[`app/admin/page.tsx`](../../app/admin/page.tsx) 登录成功后写死 `router.push("/admin/dashboard")`，不分 admin 类型。custom_admin 的权限通道**不含控制台**——控制台 4 个接口（analytics/agents/notices/users）全走 builtin-only 的 `requireAdmin()`（[`lib/session.ts`](../../lib/session.ts) 双通道：custom admin 必须走 `requirePermission`，旧接口 fail-closed），对 custom_admin 一律返 **401**。
- **B · dashboard 不健壮**：[`app/admin/dashboard/page.tsx`](../../app/admin/dashboard/page.tsx) 的 4 个 `fetch().then(r => r.json())` **不判 `r.ok`**，把 401 错误体 `{error}` 当数据写进 `data`。`data` 变 truthy → 可选链 `data?.tenantUsage` 失效 → `undefined.length` 抛错 → error boundary 接成崩页。此 bug 对 builtin admin 遇任何接口抖动（5xx/网络）同样会白屏。
- 为什么 admin-layout 的「尚未配置后台权限」兜底没接住：它只在 custom admin **可见菜单数=0** 时显示；持有 workflow 权限的角色「工作流管理」菜单可见（数≥1）→ 不走兜底 → 直接渲染会崩的 dashboard。

**修复（方案 1 + 方案 2，用户拍板）**
| 文件 | 改动 |
|---|---|
| `app/api/admin/login/route.ts` | 三个成功返回点补 `source`（`admin_table` / `custom_admin` / `user_admin`），供前端判定落地页。无新字段进 token、不改 cookie。 |
| `app/admin/page.tsx` | 登录成功后按 `data.source` 落地：`custom_admin → /admin/workflows`（它真正能进的页），其余 → `/admin/dashboard`（原行为不变）。改密码分支只 builtin 触达，保持 dashboard。 |
| `app/admin/dashboard/page.tsx` | ① 4 个 fetch 改走 `getJson()`（`r.ok ? r.json() : null` + `catch → null`），任一接口非 2xx 时 `data=null`，不再把错误体当数据；② 配额区渲染 `data?.tenantUsage?.length` / `?.map`（双保险）。降级态 = 空看板，不崩。 |

**为什么落地到 workflows 安全**：[`app/admin/workflows/page.tsx`](../../app/admin/workflows/page.tsx) 是**专为 custom admin 设计**的页（整套 `isCustomAdmin` 分支），`load()` 每个结果都 `Array.isArray(x) ? x : []` + try/catch，接口 403 只降级成空列表不崩；无 workflow 权限时 admin-layout 显示兜底页。

**未纳入本刀（留决策）**：方案 3 —— 把 dashboard / analytics 纳入 custom_admin 通道（接口改 `requirePermission`、按权限裁卡片）。需先定"自定义角色到底该不该看控制台数据"，建议单独立项。

**CI** `npx tsc --noEmit` ✅ 0 error。
**运行时冒烟**（本机 dev）：`/admin` 200；`POST /api/admin/login`（错误凭证）返回结构正常 401；`/admin/dashboard`、`/admin/workflows` 未登录均 307→`/admin`。
**未端到端验**：custom admin 真实登录 → 跳 workflows、dashboard 不崩 —— 需 dev 库 custom admin 账号，验收时实账号点验（小A 未碰 DB）。

## 条目 3 · 工作流列表 GET 500（admin/自定义角色都看不到工作流）

**现象（用户验收）**
所有角色（含内置 super_admin）打开工作流管理列表全空；dev server 日志：
`[db error] PGRST200 Could not find a relationship between 'workflows' and 'created_by'` → `GET /api/admin/workflows 500`。

**根因（6.4up 自身回归，与本会话其它改动无关）**
[`app/api/admin/workflows/route.ts`](../../app/api/admin/workflows/route.ts) GET 列表 select 用了 PostgREST 外键嵌套 `creator:created_by ( username )`（5.11up 引入，当时 v31 有 `workflows.created_by → admins(id)` 外键）。6.4up 的 `migration_v51`（等价 6.3up `v49`）为放行自定义角色建工作流**drop 了这条外键** → PostgREST 找不到关系 → 整个 GET 报 PGRST200 500 → 前端 `Array.isArray` 兜底成空列表。且 `created_by` 现可能是 `admins.id`（内置）或 `users.id`（自定义角色），单表 FK 嵌套本就语义不全。

**修复（纯代码，不动 DB / 不重加外键）**
| 文件 | 改动 |
|---|---|
| `app/api/admin/workflows/route.ts` | GET：① select 去掉 `creator:created_by ( username )`；② 取 `created_by` 集后分别查 `admins` + `users` 两表 username 并 merge（admins 优先）→ 拼 `created_by_username`。输出结构不变。 |

> 重加外键是错的——会再次堵死自定义角色建工作流（FK 23503），与 v51 的目的冲突。

**与 master2 一致性**：master2（6.5up 线，经 6.3up v49 同样 drop 外键）早已用**完全相同**的手法修过此 bug（其 `R1.12`：去嵌套 + admins/users 两表 merge）。本条等于把该修复补回 feature/6.4up（6.4up 分叉在 R1.12 之前，未带上）。

**CI** `npx tsc --noEmit` ✅ 0 error。
**未端到端验**：需登录态实际打开工作流列表确认有数据（接口在鉴权后才执行查询，curl 无 cookie 会先 401）。dev server 已重启，刷新即可验。
