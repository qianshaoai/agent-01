# 6.6up 权限后端全量补齐方案

## 目标

6.6up 不再只补工作流权限。后台权限必须形成“后端闸门为准、前端隐藏只做体验”的闭环：

- `super_admin` 仍硬全权。
- 权限管理本身、品牌/系统设置继续仅 `super_admin`。
- builtin 管理员使用默认包 + 个人 override 得出生效权限。
- custom role 从 workflow-only 升级为全资源权限。
- 后台业务 API 写接口必须先过资源权限，再执行写库。

## 权限 Key

- `CUSTOM_ROLE_PERMISSION_KEYS = ADMIN_PERMISSION_KEYS`。
- `custom-roles` POST/PATCH 允许保存全资源 key。
- 自定义角色 UI 展示完整权限矩阵，不再只展示 workflow。
- 新增 `user_group.*.{org,all}`：
  - `user_group.read.org/all`
  - `user_group.create.org/all`
  - `user_group.update.org/all`
  - `user_group.delete.org/all`

## 默认包与迁移

- `migration_v52_permission_v2.sql` 已刷新为全量 seed：
  - `system_admin` 117 keys。
  - `org_admin` 68 keys。
  - 总计 185 条。
- 新增 `migration_v53_permission_66_full_backend.sql`：
  - 给已跑 v52 的环境增补 `user_group` 默认包。
  - 幂等，可重复执行。

## 后端鉴权模型

- 新增统一 actor 入口：`requireAdminActor()`。
- actor 来源：
  - builtin admin：`admin_table` / `user_admin`。
  - custom admin：`custom_admin`。
- 后台业务 API 统一调用 `requireAccess(actor, resource, action, opts)`。
- `PERMISSION_V2_ENFORCE_RESOURCES=none` 只让 builtin 回退旧逻辑；custom admin 没有旧角色兜底，始终按 custom role permissions 判定。
- 审计日志写入 actor 信息，custom admin 以 `custom_admin` 来源进入审计链路。

## API 覆盖口径

本期后端闸门按资源映射：

- `agent`：read/basic.update/enable/delete。
- `agent_draft`：read/create/update/publish/duplicate/test/delete。
- `knowledge_base`：read/create/update/delete，文档上传/重建/删除按 KB update。
- `model_provider`：read/create/update/delete/test。
- `notice`：read/create/update/delete。
- `user`：read/create/enable/role.update/tenant.transfer/department.assign/team.assign/password.reset/delete；批量跨组织调动必须是 `user.tenant.transfer.all`。
- `tenant`：read/create/update/delete，平台级资源只认 `.all`。
- `dept` / `team`：read/create/update/delete，按所属组织 scope 判定。
- `category` / `wf_category` / `category-display`：统一映射到 `category.read.all` / `category.create.all` / `category.update.all` / `category.delete.all`，不新增 `wf_category` 独立 key。
- `workflow`：read/create/update/enable/duplicate/delete；步骤写、步骤删按 workflow update；workflow duplicate 按 workflow duplicate。
- `scope-tree` / `workflows-compact` / `workflow-scope-order`：按 `workflow.read/update` 与目标 org/dept/team scope 收口；`PERMISSION_V2_ENFORCE_RESOURCES=none` 时 builtin 回退旧 `isWorkflowConfigAdmin`。
- `user_group`：read/create/update/delete，成员增删按 update。
- `audit/logs/analytics`：统一按 `audit.read.org/all`。
- `resource-permissions`：读需目标资源 read；增删需目标资源 update 或 `basic.update`。

仍保持 super-only：

- `/admin/permissions` 及相关默认包/override/custom-role 管理入口。
- 品牌、登录展示、Logo、联系二维码等系统设置。

## 生效开关

`PERMISSION_V2_ENFORCE_RESOURCES` 支持：

- `all` 或未设置：全资源 enforce，6.6up 默认。
- `none`：紧急回滚 builtin 权限到旧逻辑。
- CSV：灰度指定资源。

支持资源：

```text
workflow,agent,agent_draft,knowledge_base,model_provider,notice,user,tenant,category,dept,team,audit,user_group
```

## 前端配套

- `/api/admin/me`：
  - builtin 返回 effective permissions。
  - custom 返回 custom role permissions。
- `AdminLayout`：
  - custom 菜单按 `requiredAnyPermissions` 展示。
  - 权限管理、品牌设置继续 super-only。
- 自定义角色 Tab：
  - 从 `/api/admin/permission-keys` 读取 `custom` 全量 key。
  - 使用完整 `PermissionMatrix`。

## 验收

静态验证：

```bash
npm run seed:check
npm run ci:typecheck
npm run ci:lint
```

构建验证：

```bash
NODE_OPTIONS='--max-old-space-size=4096' npx next build --webpack
```

smoke：

```bash
npx tsx scripts/permission-backend-smoke.ts
```

关键场景：

- custom role 只有 `kb.read.org`：只能看本组织 KB，不能创建/删除 KB，不能访问 workflow API。
- custom role 有 `provider.update.org`：只能改本组织 provider，跨组织和全局 provider 返回 403/404。
- builtin org_admin 被 revoke `notice.delete.org`：DELETE notice 返回 403，恢复 grant 后允许。
- 无目标资源 update 权时，禁止修改 agent/workflow 的 `resource_permissions`。
- 权限管理和品牌设置即使被写入非 super 权限，也仍返回 403。
