## Phase 0 · 共用基建（已完成）

A / B 两半的共用前置工作，必须先做。本 commit 不动业务路由，仅落 DB schema +
工具库 + 审计基础设施。

### 改动

1. **新增 [`supabase/migration_v43_scoped_ownership.sql`](../../supabase/migration_v43_scoped_ownership.sql)**
   - `model_providers` + `knowledge_bases` 各加 `tenant_code TEXT NULL` 列 + 单列 BTREE 索引
   - 存量数据默认 NULL（= 平台公共），与现有行为完全兼容
   - 不加 FK 到 `tenants(code)`（项目惯例软引用 + 应用层校验）
   - RLS 仍 DISABLE（与现状一致）
   - 全部 `IF NOT EXISTS`，可重跑

2. **同步更新 [`supabase/MIGRATIONS.md`](../../supabase/MIGRATIONS.md)** 加 v43 索引条目
   - 标注【🔑 RBAC 必跑】+ 5.30up 后端依赖说明（不跑就 5xx）

3. **新增 [`lib/scoped-access.ts`](../../lib/scoped-access.ts)** —— A/B 半共用 ownership 工具库
   - 5 个核心同步 helper：`listScopeFilter` / `canReadRow` / `canWriteRow` /
     `resolveCreateOwnership` / `sanitizeUpdatePatch`
   - R2 §6 · `validateTenantCode(code)` async helper：查 `tenants.code` 存在
   - R2 §4 · `scanReferences(kind, id)` async helper：扫资源引用面（含 draft JSON `.contains()` 查询）
   - R2 §1 · `requireWriteAccess(admin, allowedRoles)` 路由层双闸总闸门
   - `ScopeAdminNoTenantError` 自定义错误类（防 org_admin 缺 tenantCode 走兜底）
   - 所有 helper 对 `admin.role === "org_admin" && !admin.tenantCode` **全部 fail-closed**
   - `listScopeFilter` 用 OR filter string 返回，避免泛型 QueryBuilder 依赖

4. **改 [`lib/audit.ts`](../../lib/audit.ts)** —— R1 §5 审计基础设施补全
   - `AuditResourceType` 加 `knowledge_base`
   - `resolveResourceTenantCode` 加 `model_provider` / `knowledge_base` 两个 case，从对应表读 tenant_code

## Phase A · API 管理 RBAC 改造（已完成）

A 半实施。**所有路由都按方案 R2 §1 双闸 + §2 fail-closed + §3 embedding + §4 零引用 +
§6 validateTenantCode 执行**。

### A.1 · model-providers 6 路由

- [`model-providers/route.ts`](../../app/api/admin/model-providers/route.ts)
  - GET：接 `listScopeFilter` → org_admin 仅看公共 + own；super/system 全可见
  - POST：`requireWriteAccess(["super_admin", "org_admin"])` 排 system_admin；
    embedding 强制平台公共（三种身份都拦）；显式 `tenant_code` 调 `validateTenantCode`；
    `resolveCreateOwnership` 注入 tenant_code（org_admin 强制本组织 + 二次 validateTenantCode）

- [`model-providers/[id]/route.ts`](../../app/api/admin/model-providers/[id]/route.ts)
  - GET：删 `org_admin 403`，改用 `canReadRow` 判归属；不可见 → 404 屏蔽（防 id 探测）
  - PATCH：白名单 + load row → `canWriteRow` → `sanitizeUpdatePatch` 剥离 org_admin 的 tenant_code；
    embedding tenant_code 不可改成非 NULL；validateTenantCode；
    **R2 §4 · 转让 tenant_code 走零引用阻断**（`scanReferences`）
  - DELETE：白名单 + canWriteRow；保留现有引用阻断改用 `scanReferences` helper（同口径覆盖
    agents + drafts，且修了旧 inline 实现误读 `data.count` 的隐患）；
    DELETE 前 await `resolveResourceTenantCode` 缓存归属

- [`model-providers/[id]/test/route.ts`](../../app/api/admin/model-providers/[id]/test/route.ts)
  - 删 `org_admin 403`，改用 `canReadRow` + `canWriteRow`（org_admin 仅可测 own）
  - 写白名单含 system_admin（test 是只读探针，沿用 5.14up 现状）

### A.2 · agent-drafts 5 条链路（R1 §2 草稿链路 RBAC 收口）

- [`agent-drafts/route.ts`](../../app/api/admin/agent-drafts/route.ts) POST：
  入参 `provider_id` + `builder_config.knowledge_base_ids[]` 全部 `canReadRow`，任一不可见 → 422

- [`agent-drafts/[id]/route.ts`](../../app/api/admin/agent-drafts/[id]/route.ts) PATCH：同上

- [`agent-drafts/[id]/duplicate/route.ts`](../../app/api/admin/agent-drafts/[id]/duplicate/route.ts) POST：
  **软降级** — 源不可见 provider → NULL；源不可见 KB → 从 array 移除；
  响应里返 `strippedIds: { provider, kbs }` 供前端 toast 提示

- [`agent-drafts/[id]/test-chat/route.ts`](../../app/api/admin/agent-drafts/[id]/test-chat/route.ts) POST：
  provider `canReadRow` 失败 → 403 硬阻断；KB ids 静默过滤不可见的（不阻断对话）

- [`agent-drafts/[id]/publish/route.ts`](../../app/api/admin/agent-drafts/[id]/publish/route.ts) POST：
  provider canReadRow 失败 → 403；KB canReadRow 失败 → 403（与 test-chat 不同：publish 硬阻断）
