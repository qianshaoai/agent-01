## Phase A · R4 收口（小B 第四轮验收 3 项）

R4 反馈给的 4 项：#1 #2 #3 是 A 半范围、本 commit 修；#4 是 B 半的 KB detail page，
**写在变更记录里 cc B 半同口径修**（model-providers/page.tsx 的 `canWriteProvider` /
`canTestProvider` 拆分模式可直接复用到 KB UI）。

### #1 · publish provider select 漏 `tenant_code` 导致 org_admin 永久 403（🔴 阻断）

[`publish/route.ts:207`](../../app/api/admin/agent-drafts/[id]/publish/route.ts) 加载
provider 的 select 子句没带 `tenant_code`，下方 `canReadRow` 拿到的 row 里该字段是
`undefined`：

- `undefined === null` 为 false
- `undefined === admin.tenantCode` 为 false
- 所以 org_admin 即便用本组织 / 平台公共 provider 也会被 403

**修法**：select 子句补 `tenant_code`。

### #2 · duplicate 仍保留 org_admin 只能复制自己的硬限制（与 R1 §2 软降级冲突）

[`duplicate/route.ts:49-51`](../../app/api/admin/agent-drafts/[id]/duplicate/route.ts)
仍是 "org_admin && created_by !== adminId → 403"，方案 R1 §2 要求复制是"拿别人模板
改造"的高频路径，应允许复制 super/system 创建的"平台 demo 模板"。

**修法**：放宽口径为"自己 + super/system 创建的草稿"皆可复制，**仍禁止复制别 org_admin
的草稿**（隐私 + 越权防护）。实现：查 `src.created_by` 在 admins 表的 role，找不到则
回退查 users 表（5.28up 后台账号可能在 users 表里）；最终 role 非 super/system → 403。
不可见的 provider/KB 仍由现有剥离机制托底。

### #3 · 前端 model-providers 页混淆"归属"和"可写"两个概念（🟡 UX 不一致）

旧 `canEdit = ownership !== "other"` 导致：

- **org_admin 看平台公共**（`ownership="platform"`）→ canEdit=true，但后端 canWriteRow 拒
- **system_admin 看任何 own**（`ownershipOf` 把 super/system 都标 own）→ canEdit=true，
  但后端 API 写白名单排了 system_admin → 报错

**修法**：

1. `ownershipOf(p, me)` 改成**纯描述**——平台 / 本组织 / 其他组织；不再掺杂"我能不能改"
2. 新增 `canWriteProvider(p, me)` 与后端 `requireWriteAccess(["super_admin","org_admin"])`
   + `canWriteRow` 严格同口径：
   - super → 全可写
   - system → 全禁（API 写白名单排）
   - org_admin → 仅 own
3. 新增 `canTestProvider(p, me)` 与后端 test 白名单同口径（含 system_admin，但 org_admin 仅 own）
4. 列表按钮：编辑/启停/清空Key/删除 用 `canWrite`；测试用 `canTest`；徽章用 `ownership`
5. title 文案差异化：system_admin "仅可查看 / 测试"、平台公共 "仅超级管理员可改"、
   其他组织 "非本组织资源" —— 让 admin 看到 disabled 时知道为什么

### #4 · KB 详情页前端未灰显（B 半范围，未在本 commit 修）

[`knowledge-bases/[id]/page.tsx:351`](../../app/admin/knowledge-bases/[id]/page.tsx) 的
编辑 / 启停 / 删除 / 上传 / 重建 / 删文档 按钮没按 ownership 灰显。

**cc B 半**：可直接复用 A 半 R4 #3 的拆分模式——`ownershipOf` + `canWriteKB(p, me)`
（system_admin 与 super 等同全写，KB 矩阵沿用 5.19up 现状）+ 按钮文案差异化。
后端 KB 已正确校验，前端只是 UX；不阻断 Phase Z 验收（admin 体验差但安全无洞）。
