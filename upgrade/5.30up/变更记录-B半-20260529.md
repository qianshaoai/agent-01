## Phase B · KB 路由 RBAC 改造

### B-1 · KB 列表 / 新建（[`app/api/admin/knowledge-bases/route.ts`](../../app/api/admin/knowledge-bases/route.ts)）

- **删** `denyKbAdmin` —— org_admin 不再被一刀切拒
- **GET**：所有 admin 角色都能查询；用 `listScopeFilter(admin)` 拼 `.or()` 过滤 ownership
- **POST**：
  - R2 §1 双闸门：`requireWriteAccess(admin, KB_WRITE_ROLES)` —— 含 system_admin（KB 沿用现状全写，区别 API 管理 R2 §1 矩阵）
  - R2 §6：payload 显式带 `tenant_code` 时先 `validateTenantCode` 校验 tenants.code 存在性
  - 计算 ownership：`resolveCreateOwnership(admin, payload)` —— org_admin 强制注入 `admin.tenantCode`；super/system 沿用 payload；org_admin 缺 tenantCode → `ScopeAdminNoTenantError` 路由 catch 后返 403
  - org_admin 还要 `validateTenantCode(admin.tenantCode)` —— 防 org 已删
  - DB INSERT 写入 `tenant_code` 列
  - R2 §5 新加 `writeAuditLog({ action: "create", resourceType: "knowledge_base", resourceTenantCode: ownership.tenant_code })` —— 原 POST 根本没写审计

### B-2 · KB 详情 / 改 / 删（[`app/api/admin/knowledge-bases/[id]/route.ts`](../../app/api/admin/knowledge-bases/[id]/route.ts)）

- **GET**：
  - 先 load row → `canReadRow(admin, row)` 失败 → 404（不是 403，与方案"404 vs 403 屏蔽"一致，防 id 探测）
  - **R1 §4**：`org_admin` 不返 `referencedByAgents: [{id,name}]` 列表（防 agent 名跨组织泄漏），改返 `referencedByAgentCount: number`；super/system 仍返完整名单
- **PATCH**：
  - 双闸门 + load → `canWriteRow` → 404 屏蔽
  - org_admin 额外 `validateTenantCode(admin.tenantCode)`
  - 入参拼 `rawPatch`（含 `tenant_code` 字段）→ `sanitizeUpdatePatch(admin, rawPatch)` 剥离 org_admin 的 `tenant_code` 字段
  - super/system 转让 `tenant_code` 到某 org → 先 `validateTenantCode(new_code)`
  - **R2 §4** 零引用模式：检测到 `patch.tenant_code !== existing.tenant_code` 时跑 `scanReferences("knowledge_base", id)`，引用面 = `agent_knowledge_bases` + `agent_drafts.builder_config.knowledge_base_ids` JSON；总计数 > 0 → 422 + 描述
  - R2 §5：补 `writeAuditLog({ action: "update", detail: { fields } })`
- **DELETE**：
  - 双闸门 + load → `canWriteRow` → 404
  - org_admin 额外 `validateTenantCode`
  - R2 §4：`scanReferences("knowledge_base", id)` 替换原裸 `eq("kb_id", id).count`（**新增对 draft JSON 引用面的扫描**）
  - R2 §5：DELETE 前先 `resolveResourceTenantCode("knowledge_base", id)` 缓存 tenant_code → 删完写审计

### B-3 · KB 文档 列表 / 上传（[`app/api/admin/knowledge-bases/[id]/documents/route.ts`](../../app/api/admin/knowledge-bases/[id]/documents/route.ts)）

- **GET**：父 KB load → `canReadRow` → 404
- **POST**：
  - 双闸门 + 父 KB load → `canWriteRow` → 404（防 org_admin 把文档塞到别 org 的 KB）
  - org_admin 额外 `validateTenantCode`
  - R2 §5 新加上传审计：`{ resourceType: "knowledge_base", resourceId: kbId, detail: { document_id, filename, file_type } }`（资源仍记父 KB，简化粒度，与方案 §5 表一致）
  - 后续 storage upload / DB insert / `after(ingestDocument)` 全保留不动

### B-4 · KB 文档 删除 / 重建索引（[`app/api/admin/knowledge-bases/[id]/documents/[docId]/route.ts`](../../app/api/admin/knowledge-bases/[id]/documents/[docId]/route.ts)）

- **DELETE**：双闸门 + 父 KB `canWriteRow` 404 屏蔽 + `validateTenantCode` + 审计 `{ action: "delete", detail: { document_id, filename } }`
- **POST (reindex)**：双闸门 + 父 KB `canWriteRow` + `validateTenantCode` + 审计 `{ action: "update", detail: { document_id, filename, reindex: true } }`；原子 status 翻转保留不动
