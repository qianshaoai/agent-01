## 背景

用户搞到中转 key `https://claude.redcodeai.cn/v1/messages`，PowerShell 实测协议为 Anthropic
原生 messages API（非 OpenAI 兼容）。本期在 `lib/adapters/index.ts` 内联新增
anthropicStream，把 `anthropic` 加入 platform 体系，让 admin 能用 claude 系列模型。

⚠️ **已知不可改的限制**：redcodeai.cn 中转在请求转 Anthropic 前注入「Kiro 开发助手」
system prompt，本平台代码改不了。preset hint 显式提示风险，用户接受。

### Phase 1 · lib/adapters/index.ts 内联 anthropicStream

R2 §2 决定：与现有 5 个 adapter（cozeStream / difyStream / yuanqiStream / qingyanStream /
openaiCompatibleStream）同风格内联在 `lib/adapters/index.ts`，**不新建 anthropic.ts**——
因为 `parseSSEStream` 是 index.ts 内部 helper（无 export）。

实现要点（R2 收口后的最终口径）：

1. **R2 §7 · attachments 直接 throw**（不 silent drop · 防上线后才暴露图片失效）：
   ```ts
   if (messages.some((m) => m.attachments?.length)) {
     throw new Error("[anthropic] 多模态 attachments 暂不支持，请先移除或换 platform");
   }
   ```

2. **抽 system prompt → 顶层 body.system 字段**（Anthropic 协议要求；chat route 已把
   system_prompt 塞进 messages[0].role=system，adapter 反向抽出来）

3. **R2 §4 · temperature 不默认塞**（Opus 4.7/4.8 不支持非默认采样参数，传了会 400）；
   admin 在 modelParams 显式配置时透传

4. **R2 §5 · max_tokens 不 clamp**（Sonnet/Haiku 64k、Opus 4.8 128k，由上游 enforce）

5. **R2 §3 · 认证 header 按 endpoint host 自动判断**：
   - `api.anthropic.com` → `x-api-key: <key>`（官方协议）
   - 其它（中转）→ `Authorization: Bearer <key>`（兼容现行 redcodeai.cn 中转）

6. **R2 §6 · retry 4xx 不重试**（用 `lastErr + break` 显式分流，修了 R0 草图中 try 内
   throw 被同 catch 捕获再循环的 bug）

7. **SSE 解析**（复用 `parseSSEStream` 的 event-prefixed 支持）：
   - `event: message_start` → 拿 `usage.input_tokens` 缓存
   - `event: content_block_delta` + `delta.type=text_delta` → yield `delta.text`
   - `event: message_delta` → 多次出现累计取最后一次 `usage.output_tokens`
   - `event: error` → **必须 throw**（让 chat route 落错误分支，不 silent return null）

8. **token 用量 try/finally 兜底**：流中断 / 502 截断时仍调 `onUsage`，防 logs.prompt_tokens
   永远 0。`input_tokens → prompt_tokens`、`output_tokens → completion_tokens` 字段映射

dispatch 加 `case "anthropic": yield* anthropicStream(messages, config); break;`
